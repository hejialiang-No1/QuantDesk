# QuantDesk v1.2.0 Release Notes

**美股量化终端 · 大批量扫描版** · 2026-09-19

---

## 这一版做了什么

量化选股的扫描上限从 150 只提升到 **1000 只**，档位扩展为 7 档：
**50 / 100 / 150 / 200 / 300 / 500 / 1000**。

顺带修掉一个从 v1.0.2 起就潜伏的**估值字段取错**的 bug —— 它会让「全市场扫描」和「个股详情页」
对同一只股票给出相反的估值结论。

---

## 一、扫描规模与实测性能

| 档位 | 并发 | 请求间隔 | 本机实测耗时 | 取数成功率 |
| --- | --- | --- | --- | --- |
| 50–150 | 3 | 180ms | 约 10–15 秒 | ~99% |
| 200–300 | 5 | 130ms | **18.4 秒**（300 只，含排行 3.2s） | 99.3% |
| 500–600 | 6 | 100ms | 约 25 秒 | — |
| 1000 | 8 | 80ms | **42.6 秒**（含排行 7.9s） | 99.4% |

耗时随规模增大而**人均下降**（300 只 51ms/只 → 1000 只 35ms/只），因为并发档位是跟着规模走的。
界面会显示每档的预计耗时，扫描中实时显示进度与剩余时间。

压测脚本随版本提供：`npm run scan-load -- 1000`

---

## 二、为了跑 1000 只做的四件事

单纯把上限数字调大是没用的 —— 会变成「点了之后卡十分钟然后超时」。实际要解决四个问题：

### 1. 全市场列表要能翻页

东财排行接口**每页最多只返回 100 条**（实测传 `pz=200` 也只给 100），所以 1000 只要翻 10 页。
新增 `datasource.rankAll()` 封装翻页、去重、限流与进度回调。

一个容易忽略的细节：**单页失败不整体失败**。
翻到第 7 页被限流时，如果直接抛错，前 6 页的 600 只就白拿了 —— 现在保留已取到的部分继续。

### 2. 限流参数要能动态调整

1000 只若仍按「3 并发 + 180ms 间隔」排队，光排队就要 60 秒。
新增 `datasource.setThrottle()`，并按规模自动调档。

★ 它返回**恢复函数**，扫描结束在 `finally` 里复位。
不恢复的话，一次激进扫描会把全局限流参数永久留在高并发档，之后所有请求都贴着限流边缘跑 ——
这种「一次操作污染后续所有行为」的问题极难排查，所以必须成对出现。

### 3. 别再逐只补行情

1000 只逐一请求实时行情，既慢又必然被限流。
但排行榜返回的行**本身就带市值和 PE**，直接复用即可 —— 这一步省掉了几百次请求，
是 42 秒能跑完的主要原因。

只有「内置池 / 自选」这类不带估值数据的候选才补，且限量（>300 只时不补，
因子层按「缺失」处理）。**宁可标为缺失，也不编造数据。**

### 4. 结果要能看、能取消

- **取消**：扫到一半发现选错池子，点取消即停，**已完成的部分结果保留**
- **分页**：每页 100 行。1000 行一次性塞进 DOM 会让滚动与列排序明显卡顿；
  排序与筛选仍作用于全量，导出 CSV 也是全量
- **档位单一数据源**：档位定义在主进程，前端通过 IPC 取用。
  两处各硬编码一份，迟早出现「前端能选 1000、后端只认 300」

## 三、修复：全市场排行的 PE 字段取错（严重）

### 问题

东方财富的 `clist` 接口与 `stock/get` 接口，**同名字段的含义不一样**：

- `stock/get` 里 `f163` 是「市盈率 × 100」
- `clist` 里 `f163` 是别的量 —— 实测返回 **5.5 亿级**数字（净利润量级）

原代码把 `stock/get` 的取法（`pickFloat(f163, f164, f162)`）直接用在 `clist` 上，
于是「全市场扫描」时的 PE 全部是错的。

### 影响

「价值」因子（PE 倒数）在全市场扫描里会给出与个股详情页**相反**的结论 ——
便宜的被判成贵，贵的被判成便宜。而这类错误**不报错**，只会让人觉得「因子好像不太准」。

### 定位与修复

逐字段对照真实 PE（来自 `quoteOne`）后确认正确字段是 **`f114`**：

| 代码 | 真实 PE | f114（正确） | f9 / f115（另一口径） |
| --- | --- | --- | --- |
| NVDA | 44.61 | **44.61** ✅ | 27.77 ❌ |
| MU | 134.35 | **134.35** ✅ | 22.73 ❌ |
| AAPL | 43.8 | **43.8** ✅ | 38.05 ❌ |
| MSFT | 27.41 | **27.41** ✅ | 27.41 |
| TSLA | 379.2 | **379.2** ✅ | 378.21 |

`f9` / `f115` 是「动态 PE」口径，偏差最大可达 6 倍（MU: 22.73 vs 134.35）。
现在排行与行情的 PE 口径完全一致，并加了冒烟测试钉住这一点。

**这个 bug 从 v1.0.2 起就存在**，此前被「扫描后逐一补行情覆盖 PE」掩盖了 ——
本次为提速改成直接使用排行数据，才把它暴露出来。

### 同时修复

`emRank` 未取流通市值字段，导致「规模」因子在排行榜扫描中失真。

## 四、其他改进

- **候选池自动补齐**：内置池（标普 500 权重股 70 只）不足所选档位时，
  自动用全市场成交额榜补齐，并在结果里标注「其中 N 只来自全市场补齐」。
  **不会**静默只扫 70 只却让你以为扫完了全市场
- **数据不足如实告知**：目标 1000 只但市场实际标的更少时，明确提示
  「实际只凑到 N 只（数据源已翻到底）」，而不是默默返回一个短列表
- **大结果集裁剪**：1000 只全量（含完整 metrics + signals + factor.raw）回传有几 MB，
  IPC 序列化与渲染都会卡，超出 300 只时只回传界面真正用到的字段

## 安装

1. 下载 `QuantDesk-1.2.0-arm64.dmg`（Apple Silicon：M1 / M2 / M3 / M4）
2. 双击挂载，把 QuantDesk 拖入 Applications
3. 首次打开若被 Gatekeeper 拦截：

```bash
sudo xattr -dr com.apple.quarantine /Applications/QuantDesk.app
```

或使用仓库内的一键安装脚本（会自动处理签名与代理残留问题）：

```bash
npm run install:local -- --launch
```
