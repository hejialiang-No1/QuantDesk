# QuantDesk v1.1.0 Release Notes

**美股量化终端 · 机会雷达版** · 2026-09-19

---

## 这一版做了什么

v1.0.2 让 QuantDesk 从「看图工具」变成了「能交易的终端」。v1.1.0 补上的是**研究环节**：
在你决定买什么之前，把「有哪些上行理由」「有哪些下行风险」「最近发生了什么」「接下来会发生什么」四件事
**基于真实数据**摆在一张桌子上。

核心是一个新视图：**机会雷达**。

---

## 一、机会雷达（新视图）

一次扫描，把 40 只候选压成一张表，每只都给出：

| 输出 | 说明 |
| --- | --- |
| **暴涨潜力分** | 9 维度加权：弹性 22 / 波动压缩 16 / 量能 14 / 动量 14 / 位置 12 / 相对强度 8 / 空头燃料 8 / 催化 6 / 流通盘 6 |
| **A / B / C / D 等级** | A 级为多维度共振，D 级不建议按此逻辑参与 |
| **机会点清单** | 每条都附「触发它的原始数值」，例如 `RSI(14) = 78.3`、`量比 1.42，当日 +3.15%` |
| **风险点清单** | 同样附原始数值，含严重度评分 |
| **触发条件** | 具体到可观察：`有效突破 52 周高点 $236.54（收盘价站上并守住 2 日）` |
| **失效条件** | `跌破 MA20 $111.29 且次日无法收回，视为短期逻辑失效` |
| **风险标记** | 与收益想象并列展示，不缺省 |
| **新闻与情绪** | 句子级打分（见下文） |
| **未来事件** | 距财报天数、空头回补天数、分析师目标价 |

### 三条设计原则（也是它和「AI 随口点评」的区别）

1. **没有数据支撑的判断一律不输出。** 每条结论都带 `evidence` 字段，界面上能展开看到原始数值。
2. **结论与证据必须同屏。** 不允许出现「综合评分 8.7 分」这种无法复核的东西。
3. **风险与机会并列。** 每只候选都必须同时给出失效条件 —— 下单前先确定「什么情况下我承认自己错了」。

### 关于「可能暴涨」的诚实说明

**「暴涨潜力分」衡量的是弹性与形态特征，不是上涨概率。**

高分只意味着「如果它动，幅度会很大」—— 下跌同样被放大。所以每只候选都并排列出了 `riskFlags`。
历史上暴涨行情出现前的共同特征（波动压缩、量能异动、相对强度领先、空头燃料）在这里被量化成打分，
用来把「值得盯的 20 只」从「500 只」里筛出来，**它不告诉你方向**。

## 二、量化选股：6 因子 → 16 因子 + 13 套预设策略

### 因子库

原 6 因子（动量 / 价值 / 质量 / 低波 / 规模 / 盈利修正）保留，新增 10 个：

`趋势结构` `突破强度` `量能异动` `波动弹性` `波动压缩` `均值回归` `短期异动` `回撤健康度` `流动性` `相对强度`

每个因子都标注了口径类型：**价格实算** / **部分口径** / **代理口径**。
其中「质量」与「盈利修正」仍是价格行为代理（本地拿不到 ROE 与分析师一致预期），**字段上明确标注，不冒充实盘因子**。

### 13 套预设策略

把「选股」从一堆散装因子，提升为**可解释的交易假设**。每套都回答了三个问题：
它在赌什么逻辑（`rationale`）、门槛是什么（`filters`）、以及**最容易在哪里亏钱**（`watchOut`）。

| 预设 | 赌什么 | 最容易亏在哪 |
| --- | --- | --- |
| 动量核心 | 动量效应延续 + 趋势在位 | 趋势反转时连续吃亏，风格切换期最差 |
| 52 周突破 | 新高附近上方无套牢盘 | 假突破是主要亏损来源 |
| 放量启动 | 量能先于价格异动 | 高位爆量可能是出货 |
| 波动压缩待爆发 | 低波动聚集后跟着高波动 | **方向未知**，向上向下概率接近 |
| 超卖反弹 | 好公司的坏日子 | 超卖可以更超卖，接刀风险 |
| 小盘高弹性 | 小盘定价效率低 | 流动性风险最大 |
| AI 算力链轮动 | 产业链内部资金轮动 | 板块同涨同跌，集中度过高 |
| 低波质量 | 低波异动长期有效 | 不会给你暴涨，价值在于活得久 |
| 深度价值 | 估值回归 + 质量过滤 | PE 口径看不出「一次性收益」陷阱 |
| 财报前布局 | 财报漂移效应 | **财报是最大的跳空风险** |
| 相对强度领跑 | 资金流向就是理由 | 系统性调整时跌幅更大 |
| 防御配置 | 环境不明时降波动 | 防御 ≠ 不亏，只是亏得慢 |
| 高弹性候选 | 多维度共振筛选 | 观察清单 ≠ 买入清单 |

### 股票池

从 6 个扩到 **17 个**，新增：核电与铀 / 量子计算 / 生物科技 / 金融科技 / 加密相关 / 机器人自动化 / 国防航天 / 消费零售 / 高贝塔弹性 / 中小盘成长 / 高股息防御。

## 三、新闻与事件

### 新闻：句子级情绪（这是关键设计）

一只股票经常只是被「顺带提及」。两个真实例子：

- 标题「智谱AI概念大爆发，传智教育狂揽7连板」—— 看起来与你的股票无关，
  但正文写着「Palantir 业绩双双超预期，刺激股价盘后涨超 14%」。**这是明确的利多。**
- 标题「段永平再度增持泡泡玛特」—— 正文提到「我会卖点 PLTR 的 put」。**这对 PLTR 是相关信息。**

所以本版实现的是：**先定位「提到这只股票的那句话」，再对那句话打分**。
标题命中 = 主体新闻（权重 1.0）；仅正文命中 = 提及（情绪按 0.7 折算）。
同时做**相关性过滤**，剔除搜索关键词带来的泛市场噪音。

### 未来事件日历

| 类别 | 来源 | 说明 |
| --- | --- | --- |
| 宏观日程 | Federal Reserve / BLS / BEA / Census | 官方已公布：FOMC、CPI、非农、PCE、GDP、PPI、JOLTS |
| 个股财报 | nasdaq 财报日历 | 含 EPS 一致预期、盘前/盘后、市值 |
| 分红 / 拆股 | nasdaq 日历 | 除权日、派息日 |
| 期权到期 | 规则计算 | 每月第三个周五；3/6/9/12 月标注为三重巫日 |
| 惯例类 | 规则推算 | ISM PMI、密歇根信心 —— **标注为「估算」** |

所有事件都带 `source` 与 `estimated` 字段，界面上会区分显示，不会把推算日期冒充官方公告。

## 四、修复的 Bug（这一版最重要的部分）

### 1. 事件日历永远返回空（静默失效）

`events.dayStart()` 不接受时间戳入参，而 `upcoming()` 默认传的就是 `Date.now()` 的返回值 ——
于是 `from` 变成 `NaN`，**所有日期比较都是 false**，整个日历返回空数组，而且不报任何错。
你只会觉得「怎么老是没事件」。已补上 `typeof d === 'number'` 分支，并加了回归测试钉死。

### 2. 单一风险压过三条机会（归一化错误）

`insight` 计算综合分时，分母用的是「实际命中项数的权重和」。
结果：只有 1 条风险时，那一条被赋予 **100% 权重**，
一条 90 分的风险直接压过三条机会 —— 明明在上升趋势里也判「偏空」。
改为固定分母后，命中项少的一侧分数自然低（理由越少，说服力越弱）。

### 3. 暴涨雷达三个维度失去区分度

实测发现 `volume` 均值 16.7、`position` 恒为 50、`float` 全为 0 —— 三项合计 **26% 的权重形同虚设**：

- `volume`：量比在 0.8~1.0 之间时算出负数被 clamp 到 0，于是「量能与均量持平」反而拿 0 分
- `position`：-25% 与 -55% 的深度回撤被一视同仁给 50 分
- `float`：上界只到 400 亿，所有千亿级大票一律 0 分

已全部改为分段平滑映射。修复后各维度 min/max 跨度恢复正常。

### 4. 腾讯行情兜底源静默失效

`qt.gtimg.cn` 只认 `usNVDA`（不带后缀），带 `.OQ` 会返回 `v_pv_none_match`。
原实现只用了带后缀的写法，**这个源每次都在失败，但从不报错**。现改为两种写法依次尝试。

### 5. 新闻被泛市场噪音污染

东财搜索是全文检索，搜 `PLTR` 会返回「智谱AI概念大爆发」这类完全无关的稿子。
不过滤的话，个股情绪分就变成了大盘情绪分的复读机 —— 看上去有数据，实际与这只票毫无关系。
已加入相关性过滤 + 句子级情绪。

### 6. 打包/发布脚本版本号硬编码

`build-dmg.sh` 与 `release.sh` 写死版本号，会导致「代码发新版、dmg 文件名和 Release 还是旧版」，
而且构建照常成功、不报错。现统一从 `package.json` 推导。

## 五、新增命令行工具

三个脚本，与 GUI **共用同一份** datasource 与算法模块（如果两边结果不一致，问题一定在模块里）：

```bash
# 跑一次机会雷达（不依赖 Electron）
npm run radar -- --universe=highbeta --limit=30 --news=12 --extras=10

# 把多次扫描汇总成 HTML / Markdown 报告
npm run report -- --in-dir=/tmp --glob=radar- --out=build/report/radar.html --md

# 多源行情交叉验证（防止脏数据静默污染下游所有计算）
npm run verify -- --symbols=NVDA,MU,DELL,AMD
```

**`verify` 值得单独说**：行情错了，后面所有因子、评分、风险点全是错的，而且不会报错 ——
典型症状是「数字看起来都挺合理，只是全都偏了一点」。
这个脚本拿同一批标的去问 4 个独立数据源（东财 / 腾讯 / 新浪 / nasdaq），
把偏差 > 0.5% 的挑出来，并单独报告「只有一个源可用」的标的（**无法交叉验证 ≠ 数据正确**）。

**关于「增强源」**：nasdaq 的数据最全，但国内网络常不可达。
所以它被设计为**可选增强**：通了就有更丰富的数据，不通也不影响主流程，
界面上会明确显示「本次未取到 XX 数据」，**不会把「没有数据」渲染成「没有风险」**。

数据源不可达时会自动降级并在界面上暴露降级状态。多源交叉验证（`npm run verify`）实测
腾讯 = 新浪 = nasdaq 三方价格偏差 **0.00%**。
